Vercel · GCP e2-micro · cc-mimic

Two clouds that never speak to each other

The front end runs on Vercel. The agent runs on a free GCP VM. They have no connection between them — everything is stitched together inside the visitor’s browser.

That one fact explains nearly every decision below. Vercel serves a page; the page carries a URL pointing at the VM; the browser then opens a second, entirely separate connection. Which is why the back end needs its own domain, its own TLS certificate, and CORS.

The two ways in

Only two paths reach the VM from outside, and they are unequal: one is open to the whole internet, the other only to Google’s IAP range.

Everything else, the VM starts itself

Outbound needs no firewall rule — GCP permits egress by default. This is what lets the whole design survive an IP that changes every time the machine stops.

One chat message, down the stack and back up

The browser opens a single TCP connection and holds it open for the entire reply. That is what SSE is — not polling, and not one request per token.

Three things that surprise people

Port 8000 cannot be exposed by accident

Compose uses expose:, not ports: — which creates a docker-network address and no iptables rule. Delete every firewall rule you have and uvicorn is still unreachable, because the packets have nowhere to land.

The VM has never seen its own public IP

Its NIC is configured with 10.128.0.2. GCP does 1:1 NAT outside the instance, so ip addr on the box will not show 34.60.179.53.

CORS protects browsers, not the API

A wrong ALLOWED_ORIGINS still lets the request arrive, run, and return — the browser just discards the response afterward. curl ignores it entirely. The real gate is the JWT, checked against Convex’s JWKS.

One worker is load-bearing

Sessions live in the process’s memory, so a second worker would answer half the requests with “no such session”. It also means every deploy drops all open streams.

Why the back end needs its own certificate. The page is served over HTTPS, and a browser refuses to let an HTTPS page open a plain http:// connection. A certificate can only be issued for a name, never a bare IP — which is the entire reason DuckDNS appears in these diagrams at all.
